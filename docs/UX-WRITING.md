# dwo-Forge 화면 문구 기준

창(GUI), HTML 리포트, README에 쓰는 한국어 문구의 기준입니다. 새 화면이나 메시지를 추가할 때 이 표를 따릅니다.

## 비슷한 상용 제품과 비교

dwo-Forge는 "언리얼 프로젝트에 붙여 쓰는 분석·검증 도구 + 런타임 상태 보기 + 디자인 가져오기"입니다. 같은 역할을 하는 상용 제품이 쓰는 말을 기준으로 삼았습니다.

| 역할 | 비교한 제품 | 그 제품의 표현 | dwo-Forge에 적용 |
|---|---|---|---|
| 도구를 프로젝트에 붙이기 | SonarLint Connected Mode(Bind), Sentry·Slack 연동, JetBrains RiderLink 설치 | 바인딩, 연동, 설치 | **연동** ("부착"은 하드웨어·물리적 표현이라 소프트웨어에서 쓰지 않음) |
| 품질 검사 묶음 | SonarQube, Qodana, Unreal Horde, CI 파이프라인 | 분석, 검사, 작업, 단계 | **검사**(Lens의 analyze·verify·logs 등 하나하나), **단계**(검사 안의 ST-1 같은 순서) |
| 통과 여부 | SonarQube 품질 게이트, CI 결과 | 결과, 통과/실패, 품질 게이트 | **결과** (통과·경고·실패), 리포트 제목은 **품질 게이트** |
| 문제를 목록에서 빼기 | SonarQube(무시·Won't fix), JetBrains(억제), ESLint(ignore) | 무시, 억제 | **무시** (기준선에 추가) |
| 실행 결과물 | CI 아티팩트, Horde 산출 파일 | 아티팩트, 결과 파일 | **결과 파일** |
| 프로그램 버전·업데이트 | Visual Studio, JetBrains 한국어판 | 버전, 업데이트 | **버전**, **dwo-Forge 업데이트** ("시스템"은 운영체제로 읽혀 쓰지 않음) |
| 로그 자동 스크롤 | Visual Studio 출력 창, JetBrains 실행 창 | 자동 스크롤 | **자동 스크롤** |

## 용어표

| 쓰는 말 | 쓰지 않는 말 | 비고 |

| 아키텍처 문제, 검출 항목 | 발견 | |

| 버전 | 시스템 | |
| 환경 점검, 상태 확인, 게임 실행, 검사, 가져오기 | 환경 점검 (doctor), 검사 (Validate) 등 | |

## 문장 규칙

- 안내문은 "~합니다", 요청은 "~하세요"로 끝냅니다. 버튼과 메뉴는 명사형으로 씁니다("프로젝트 연동", "게임 실행").
- 알림 제목은 "<작업 이름> 완료 / 실패"로 쓰고, 작업 이름은 한국어로 씁니다(`analyze 완료`가 아니라 `아키텍처 분석 완료`).
- 언리얼 고유 용어(Blueprint, PIE, ensure, 커맨드릿, 리다이렉터)와 파일·폴더 이름은 번역하지 않습니다.
- 설계 문서([guide.html](guide.html))의 "공장·공정" 비유는 설계 개념을 설명하는 곳에만 쓰고, 화면 문구에는 쓰지 않습니다.
