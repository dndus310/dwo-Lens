dwo-Forge 가이드

언리얼 프로젝트에 붙여 쓰는 도구 모음입니다. 세 도구를 제공합니다: Lens(분석·검증·로그 라인, 이 가이드의 대부분), DwoStateMonitor(실행 중인 게임의 실시간 상태, 예전 StateMonitor), DwoCanvas(디자인 파일 *.dwocanvas.json → UMG 위젯 블루프린트). dwo-Lens 1.x에서 이름이 바뀌었고, 부착된 프로젝트는 첫 명령 때 자동으로 옮겨집니다.

Lens는 언리얼 프로젝트에 흔적 없이 붙었다가 언제든 떨어지는 분석 공장입니다. 결정적 공정이 프로젝트를 읽고 검증하며, AI는 공정의 양 끝에서 계획과 판단만 맡습니다. DwoCanvas도 DwoStateMonitor처럼 원본은 dwo-Forge에 두고 Plugins/__DwoCanvas에 숨겨 설치하며, 제거나 uninstall 때 지웁니다(canvas-install · canvas-validate · canvas-import · canvas-remove, 자세한 내용은 plugin/DwoCanvas/README.md).

01 · Overview

한눈에 보기

요구사항 접수부터 보고까지 하나의 흐름입니다. 중간 공정은 같은 입력이면 같은 결과가 나오는 도구로만 돌아가고, 검증 게이트를 통과한 결과만 AI 판단으로 넘어갑니다.

03 · Principles

설계 원칙

모든 공정과 도구는 아래 네 가지를 지킵니다. 새 도구를 추가할 때도 이 기준으로 판단합니다.

P1 · 무결합

언제 떼어 내도 프로젝트는 그대로

모든 공정은 A 프로젝트를 읽기만 합니다. 시스템 파일은 .git/info/exclude로 이력에 잡히지 않고, .uproject는 건드리지 않습니다. 패키지를 수정하는 엔진 도구(ResavePackages 등)는 실행하지 않습니다.

P2 · 결정적 우선

도구가 먼저, AI는 마지막

사실은 도구가 추출하고 UE 규칙으로 확정합니다. 검증 게이트를 통과한 결과 중 도구로 확정할 수 없는 것만 AI가 해석합니다.

P3 · 산출물 계약

공정 간 전달은 JSON으로만

각 공정의 입출력은 버전이 있는 스키마(lens.raw, lens.graph, lens.logs 등)로 정합니다.

P4 · 실행 기록

모든 결론을 추적하고 재현

실행마다 run.json에 실행 ID, 공정별 판정과 소요 시간, 시스템 커밋을 남깁니다.

04 · Attach

프로젝트 부착

PC마다 setup.bat을 한 번 실행해 DWO_FORGE_HOME을 등록합니다. 그다음 __dwo-forge.bat 하나를 대상 프로젝트 루트에 복사해 실행합니다. 시스템 본체는 git clone으로 들어가므로 버전 확인, 업데이트, 제거를 git이 맡습니다.

STEP 1사전 확인

.uproject, 프로젝트 자체 git 저장소 여부, git, DWO_FORGE_HOME

STEP 2exclude 등록

파일을 만들기 전에 표식 블록을 먼저 기록합니다

STEP 3clone 또는 pull

시스템 저장소를 __dwo-forge/system으로 가져옵니다

STEP 4플러그인 설치

엔진 버전별로 캐시된 바이너리 복사, state.json, doctor

A 프로젝트 안의 구조

A/
├─ __dwo-forge.bat              # 제어 진입점
├─ __dwo-forge/
│  ├─ system/                   # 시스템 clone
│  ├─ data/runs/<id>/           # raw · out · run.json
│  ├─ config.json               # (선택) 규칙 덮어쓰기
│  └─ state.json
└─ Plugins/__DwoLensInspector  # 바이너리만, Source 없음

exclude 표식 블록

# 팀원이 직접 쓴 줄은 건드리지 않음
*.log

# >>> dwo-forge managed (do not edit) >>>
/__dwo-forge/
/__dwo-forge.bat
/Plugins/__DwoLensInspector/
# <<< dwo-forge managed <<<

경로는 git rev-parse --path-format=absolute --git-path info/exclude로 구하므로 worktree에서도 동작합니다.

명령동작
attach / update사전 확인 → exclude → clone/pull → 플러그인 설치 → doctor. 다시 실행하면 업데이트로 동작합니다.
analyze아키텍처 리포트와 품질 점검
verifyBP 전체 컴파일, 데이터 검증, 자동화 테스트
logsSaved/Logs, Saved/Crashes 분석, 이전 실행 대비 새 오류 표시
tools / status / doctor도구 카탈로그, 부착 버전·업데이트 여부, 환경 점검
detach [--keep-data]플러그인·exclude 블록·작업 폴더 제거, git 상태 비교, batch 자기 삭제
주의 대상 프로젝트는 자체 git 저장소여야 합니다. 상위 폴더 저장소(예: 홈 폴더 전체가 저장소인 경우)에 포함되어 있으면 부착을 거부합니다. C++ 프로젝트는 에디터 바이너리가 빌드된 상태여야 하며, Build.cs·Target.cs에 시스템 관련 내용이 섞이지 않았는지는 커밋 전에 작업자가 확인합니다.

09 · StateMonitor

DwoStateMonitor 실시간 상태

설치만 하면 코드 없이 실행 중인 게임(PIE, 독립 실행, --runtime 설치 시 패키지 게임)의 상태가 dwo-Forge 창으로 실시간 전송됩니다. 객체는 노드로, 열거형·bool 같은 필드는 상태 머신으로 보여 주고, 타임라인으로 지난 시점을 되돌려 봅니다.

사용 순서

설치 → 실행 → 보기

sm-install(에디터·PIE 전용, 패키지 영향 없음) → dwo-Forge의 State Monitor 화면 → 에디터에서 Play 또는 게임 실행(play). 게임이 127.0.0.1:47731로 자동 연결하고, GameMode·GameState·PlayerController·PlayerState·Pawn·컴포넌트를 주기적으로 보냅니다. 기본은 프로젝트가 선언한 프로퍼티만 보냅니다.

대상 추가

클래스 관찰 · BP 노드

왼쪽 관찰할 클래스에 BP_Enemy_C처럼 넣으면 그 액터들을 함께 봅니다. Blueprint에서는 Watch State Object(객체), Submit State Snapshot(구조체)으로 직접 추가합니다. 게임 스위치: -StateMonitorPort=N, -StateMonitorLive=0.

보기내용
객체 그래프소스마다 노드. 실선은 소유(컨트롤러 → Pawn → 컴포넌트), 점선은 프로퍼티가 가리키는 참조. 방금 바뀐 필드는 노란색
상태 전이열거형·bool·이름·작은 정수 필드를 상태 머신으로. 현재 상태 강조와 경과 막대, 전이 횟수, 방금 일어난 전이 깜빡임, 상태별 진입 횟수·누적·평균 시간
속성현재 값 트리(이전 값 툴팁), 변경 이력, 상태 필드 목록, JSON 복사
타임라인 · 이벤트소스별 변경 표시와 값 구간. 재생 위치를 끌면 모든 보기가 그 시점 값으로 바뀜. 이전·다음 변경으로 이동
녹화받은 메시지를 JSON Lines로 저장하고 다시 열어 같은 화면으로 재생
분석·검증 연계analyze가 제출 지점을 찾고, verify가 StateMonitor.* 테스트(12개)를 함께 실행
