dwo-Forge 3.0 · 레이아웃 시안

도구를 관리하는 런처로서의 dwo-Forge

Lens, DwoStateMonitor, DwoCanvas, 로컬 CI를 모두 같은 자격의 "도구"로 다루고, dwo-Forge는 프로젝트에 도구를 설치·업데이트·제거하고 실행하는 런처가 됩니다. 아래 세 시안은 같은 도구 모델 위에서 화면을 어떻게 나눌지에 대한 선택지입니다.

먼저 나눌 것: 연결은 런처, 설치는 도구

지금의 "연동"은 dwo-Lens 시절의 흔적으로 Lens 설치까지 함께 합니다. 런처 구조에서는 둘을 분리합니다.

프로젝트 연결 dwo-Forge

  • __dwo-forge 폴더와 실행 파일 __dwo-forge.bat
  • git 숨김(.git/info/exclude)과 연결 전 상태 기록
  • 설치된 도구와 버전 목록(state.json의 tools)
  • 연결 해제: 모든 도구 제거 후 흔적 정리

도구 설치 각 도구

  • Lens: Plugins/__DwoLensInspector 설치
  • DwoStateMonitor·DwoCanvas: 플러그인 설치
  • 로컬 CI: Jenkins 작업과 git 훅 (PC 공용 Jenkins는 처음 한 번)
  • 도구마다 설치·업데이트·제거·버전이 따로 있음

공통 도구 모델

어느 시안을 고르든 바탕은 같습니다. 런처는 도구마다 아래 정보를 한 번에 받아(__dwo-forge.bat tools --json) 카드·배지·업데이트 알림을 그립니다.

도구를 누르면 그 도구의 화면이 탭으로 열립니다. Ctrl+1~9는 "활성 도구의 n번째 탭"으로 바뀌고, Ctrl+Shift+1~9가 도구 전환입니다.

좋은 점

  • 런처 정체성이 가장 분명함: 홈이 곧 도구 관리
  • 새 도구는 아이콘 하나 + 자기 탭만 추가하면 됨
  • 설치 안 한 도구는 화면에서 사라져 단순함

아쉬운 점

  • Lens 화면 이동이 한 단계(탭) 늘어남
  • Ctrl+1~6 단축키 의미가 바뀜

확장성

  • 도구 8~10개까지 활동 바가 버팀
  • 도구별 화면 수에 제한 없음 (탭)
  • 여러 프로젝트는 제목 표시줄 전환으로

결정

C로 구현했습니다(dwo-Forge 3.0). 도구 창은 별도 OS 창이 아니라 같은 창 안의 작업 화면으로 열립니다(명령 대기열과 DwoStateMonitor 연결을 하나로 유지하기 위해). 활동 바에는 런처와 설치된 도구만 보이고, 연 도구가 자기 화면들을 펼칩니다. 아래는 결정 전의 제안입니다.

A를 이번에 구현하고, C의 "PC 구성요소"와 프로젝트 전환을 A 안에 작게 넣는 것을 권합니다. A의 홈과 도구 작업공간은 C로 가더라도 그대로 쓰이므로 버려지는 작업이 없습니다. 여러 프로젝트를 자주 오가게 되면 그때 홈을 C의 라이브러리 화면으로 키우면 됩니다.

  1. CLI: connect(연결만), tool install|update|remove <lens|statemonitor|canvas|ci>, tool update --all, tools --json. 기존 명령(attach, sm-install 등)은 그대로 동작.
  2. state.json에 도구별 설치 버전·해시 기록. 기존 연결 프로젝트는 처음 열 때 지금 설치된 도구를 읽어 채움.
  3. GUI: 홈(도구 카드, 모두 업데이트, PC 구성요소 줄) + 도구 아이콘 + 도구별 탭. 실행 기록은 Lens 탭으로.
